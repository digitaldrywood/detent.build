§1

The state machine

A detent is the catch that holds a moving part at a fixed position until it is deliberately released — the click-stop on a dial, the notch on a ratchet. Detent holds each piece of work at a defined stop on your board and only lets it advance when a gate is cleared:

Todo ──▶ In Progress ──◃── Human Review ──◃── Merging ──▶ Done
│
└──▶ Rework (unresolved feedback) ──▶ back through the gate

◃ = a gate you defined. nothing passes a gate on charm.

The board can be a GitHub ProjectV2, an issue Status field, or repository labels — Detent supplies its own Kanban view either way. The lanes themselves are workflow-defined too — the six above are the defaults Detent runs on itself.

§2

The inversion

Autonomy-first assistants keep memory and sessions, pick their own tools, and ask you to steer. Detent inverts the interaction model: you write the issue first — scope, acceptance criteria, tests, dependency order, review policy, merge rule — and the board state decides when it is eligible. It is a system, not an agent. The goal is not to replace engineers; it is to scale the judgment of engineers who already have a high bar.

§3

How it works

  1. You write the contracts. A checked-in detent.yaml machine contract plus a portable WORKFLOW.md agent contract. Gitignored *.local variants carry machine-specific overrides.
  2. You mark an issue Todo. Detent claims it, creates an isolated worktree from your checkout, dispatches a Codex agent, moves the issue to In Progress.
  3. The agent works in its own branch, runs your validation gate, opens or updates a PR.
  4. Gates decide. Human Review, in-lane wait, current-head automated review, or linked PR + green CI + quiet time. Unresolved feedback → Rework.
  5. The merge train is serialized — one rebase, CI-watch, merge at a time. Then Done.
  6. One host, many repos. global.yaml: weights, priority, pause, fair scheduling.
  7. Bugs close the loop. Detent can log the bugs it finds as issues, gate them like any other work, and ship the fix — hands-off when project config allows it.
§4

The merge train

Will it merge garbage? No — and not because we promise. Merging is serialized: one rebase, one CI-watch, one merge at a time, so concurrent candidates never invalidate each other's CI. What lands is always green.

[PR #204] [PR #199] wait ──▶ rebase #193 ──▶ ci-watch 4/6 ──▶ merge ✓ ──▶ next

§6

Contracts

detent.yaml
tracker: { mode: projectv2 }
gates:
  validate: make check
  review: automated
  merge: ci_green + quiet 10m
scheduling:
  parallel: 4
  lease: 30m
WORKFLOW.md
1. The issue is the spec.
   Do not exceed it.
2. Stay in your worktree.
3. `make check` before push.
4. Unresolved feedback → Rework.
5. Never merge. The train merges.

You can keep reading by hand too; nobody will revoke your keyboard.

§7

It builds itself

digitaldrywood/detent-orchestration is Detent's own production config, and it dispatches the agents that build Detent. It is copyable as a template. This is the whole credibility argument, and it is literally true.

§8

One host, many repos

Multi-project and multi-instance fleet governance from one host. Budget and cost caps; token / budget / rate-limit state live on the dashboard.

Install

$ brew install digitaldrywood/tap/detent # macOS
$ go install github.com/digitaldrywood/detent@latest # Go 1.26+
$ winget install detent · scoop install detent · .deb · .rpm
$ detent doctor # preflight: gh present, codex signed in, token scope

Requirements: Codex CLI signed in to your ChatGPT plan; gh assumed; a GitHub token scoped to your tracker mode. Explicit backend routing — including Claude Code — is configurable per role.

Why Codex? Detent dispatches agents non-interactively, headless, many at once — scripted codex exec runs against a ChatGPT plan you already pay for; Claude Code moved headless usage to separate Agent SDK credits (June 2026). Backend routing per role, including Claude Code, remains explicit config. Why GitHub Projects? One ID space: the Project is the board, issues are the work items, PRs are the deliverables, reviews are the conversation. Detent is the orchestrator; your config and workflow are the intelligence.
